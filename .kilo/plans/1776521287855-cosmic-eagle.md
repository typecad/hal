# Maintainability Improvement Plan

## Executive Summary

The codebase is a TypeScript-to-C++/Arduino transpiler monorepo (~42K lines across 7 packages). Three systemic issues dominate: **monolithic files**, **duplicated logic**, and **incomplete type safety**. Below is a prioritized plan addressing each area.

---

## P0 — Critical (High impact, foundational)

### 1. Split `ir/build-ir.ts` (3,862 lines) into focused modules

The file contains the entire AST-to-IR transformation. `expressionToIR()` alone is ~980 lines.

**Proposed split:**
- `ir/expression-builder.ts` — expression-to-IR conversion
- `ir/statement-builder.ts` — statement-to-IR conversion  
- `ir/class-builder.ts` — class, constructor, method processing
- `ir/namespace-builder.ts` — namespace traversal
- `ir/import-resolver.ts` — import/require handling
- `ir/ast-patterns.ts` — shared helpers: `extractRootAndChain` (currently duplicated 3x), peripheral chain detection, device accessor detection, debounce detection, interrupt detection

### 2. Complete `cpp-emitter.ts` extraction, remove module-level state

The file (2,683 lines) already has a DEPRECATED comment (lines 59-67) acknowledging this. `ExpressionRenderer` and `StatementRenderer` classes exist but coexist with the old standalone functions.

**Steps:**
1. Move all remaining emission logic from standalone functions into the class-based renderers
2. Replace 8+ module-level `let` variables with constructor-injected state on an `EmissionContext` class
3. Delete the deprecated standalone `renderExpression()` and `renderStatement()` functions
4. This also resolves the `build-ir.ts` module-level state (`hoistedNestedFunctions`, `nestedFunctionAliases`, etc.)

### 3. Complete the IR type model in `core/shared/ir.ts`

**Root cause of 150+ `as any` casts:** IR types lack fields that are set at runtime: `ownershipKind`, `interruptMode`, `configMethod`, `isAwaited`, `postfix`, `debounceMs`, `sourceSpan`.

**Steps:**
1. Audit all `as any` casts in `ownership-analysis.ts` (38 occurrences), `build-ir.ts` (9), `cpp-emitter.ts` (10), `peripheral-usage.ts` (15), `pin-mode-validation.ts` (10)
2. Add optional fields to the IR union types in `core/shared/ir.ts`
3. Replace `as any` casts with properly typed access
4. **Worst offender to fix first:** `ownership-analysis.ts` which casts `(stmt as any).ownershipKind` on nearly every line

**Target location:** `packages/cli/src/emit/utils/cpp-helpers.ts` (or split into `cpp-types.ts`, `cpp-format.ts`)

### 5. Create shared IR visitor pattern

Six validation modules each implement their own recursive IR walker:
- `ownership-analysis.ts` (walkStatement/walkExpression)
- `peripheral-usage.ts` (analyzeStatement/analyzeExpression)
- `interrupt-analysis.ts`
- `pin-mode-validation.ts`
- `try-catch-validation.ts`
- `identifier-collector.ts`

**Proposed:** Create `ir/visitor.ts` with a typed visitor:
```typescript
interface IRVisitor<T> {
  visitExpression(expr: ExpressionIR, ctx: T): void;
  visitStatement(stmt: StatementIR, ctx: T): void;
}
function walkProgram(program: ProgramIR, visitor: IRVisitor<unknown>): void;
```
Each validation module then only implements the visitor methods it cares about.

### 6. Fix `framework-avr/strategy.ts` — pervasive `any` types

Every override systematically erases type information from the parent `ArduinoStrategy`:
- `forcedIncludes(_program?: any, _ctx?: any)` 
- `generateNativePolyfills(program?: any, _ctx?: any)`
- `tryRenderCallStatement(callee: string, args: ReadonlyArray<any>, ...)`
- etc.

**Fix:** Add proper types matching the parent class signatures (`ProgramIR`, `PlatformContext`, `ExpressionIR`, `BoardConstants`).

### 7. Remove dead/duplicated code in `typecode-map.ts`

- Lines 910-974: `Num`/`Pulse`/`Shift`/`Random` handling is duplicated from lines 762-842 (the early returns make the bottom block unreachable)
- Lines 816-838: Fluent `Num` chains (`Num.map().from().to()`, etc.) emit `/* comment */` strings — either implement or remove

### 8. Resolve conflicting type guard exports in `@typecode/core`

`capabilities.ts` and `pin.ts` both export `isPWMPin`, `isAnalogPin`, `isInterruptPin` with **different implementations**. The barrel export in `index.ts` shadows the `pin.ts` versions.

**Fix:** Consolidate into a single implementation in one file, re-export from the other.

## P2 — Medium Priority

### 9. Split `transpile.ts` (1,471 lines) into pipeline stages

`transpileFile()` (~430 lines) handles: dependency graph, caching, tree-shaking, polyfill detection, framework loading, emission, output writing.

**Proposed split:**
- `transpile/dependency-graph.ts` — `collectTranspileGraph()`
- `transpile/pipeline.ts` — step-by-step orchestration
- `transpile/tree-shaking.ts` — `applyTreeShaking()`
- `transpile/output-writer.ts` — file output and source maps

### 10. Replace empty catch blocks (24 occurrences) with debug logging

Silent error swallowing in: `transpile.ts` (3), `cli-metadata.ts` (3), `arduino-cli.ts` (4), `incremental-cache.ts` (2), and others.

### 11. Replace `console.log` debug output with logger abstraction

387 console.log/warn/error calls. Non-CLI modules (`transpile.ts`, `arduino-libs.ts`) mix debug output with CLI output. A simple logger would allow configurable verbosity.

### 12. Consolidate duplicated code in framework packages

- `framework-avr/strategy.ts:158-196` — console polyfill has 7×3 near-identical overloads → extract a helper
- `framework-arduino/profile.ts` + `cli-metadata.ts` — `toArchitectureFromFqbn` defined identically in both files
- `framework-arduino/profile.ts:106-113` — AST walker only recurses into `while` bodies, missing `if/for/do/switch/try/block`

### 13. Fix `simulator` package workspace inconsistency

`simulator` is in `tsconfig.json` project references but NOT in `package.json` workspaces. Add it to workspaces.

## Implementation Order

The recommended order maximizes impact while managing risk:

1. **P0-3** (IR type model) — Unblock P0-1 and P0-2, reduces 150+ `as any` casts
2. **P0-1** (Split build-ir.ts) — Largest file, highest payoff
3. **P0-2** (Complete emitter extraction) — Already started, has roadmap
4. **P1-4** (Extract duplicated utilities) — Quick wins, reduces bug surface
5. **P1-5** (IR visitor pattern) — Unblocks cleaner validation modules
6. **P1-6** through P1-8 — Framework package fixes
7. **P2** items — Pipeline splitting, logging, consolidation
8. **P3** items — Dead code, config extraction, test improvements
