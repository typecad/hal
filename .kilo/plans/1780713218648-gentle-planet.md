# Fix All TypeScript-to-C++ Transpilation Errors

## Package Segregation
- **`packages/framework-native/src/strategy.ts`** — Native framework strategy fixes
- **`packages/cuttlefish/`** — Transpiler core fixes

---

## Part 1: Native Framework Fixes (`strategy.ts`)

### 1A. Fix `.pop()` ordering (Issue 7)
The `.pop()` → `pop_back()` regex at line 156 runs BEFORE the `__tc_pop()` regex at line 160. Since `pop_back()` doesn't return the removed element, `const last = arr.pop()` fails to compile.

**Fix:** Remove the `pop_back()` line (156) and keep only the `__tc_pop()` line. The `__tc_pop` polyfill already exists and returns the value.

### 1B. Add `.splice()` with insertion support (Issue 8)
The regex `(\w+)\.splice\(([^,]+),\s*([^)]+)\)` captures `deleteCount, item1, item2...` as one group `$3`, passing too many args to `__tc_splice2`.

**Fix:** Add a `__tc_splice3` regex + polyfill for splice with items: `arr.splice(start, count, ...items)`. The regex should use `([^,]+),\s*(\d+)\s*,\s*(.+)` to separate deleteCount from items. Actually, splice with items is hard to handle with regex because items can contain commas inside nested expressions. Instead, move splice handling to the IR level (see transpiler Part 2C).

### 1C. Fix `.unshift()` with multiple args (Issue 9)
`__tc_unshift` polyfill only accepts one value. `arr.unshift(1, 2, 3)` produces `__tc_unshift(arr, 1, 2, 3)` with too many args.

**Fix:** Change the `__tc_unshift` polyfill to use a variadic approach (or just handle single-arg case since that's 99% of usage). For the regex, the current approach already captures all args. Add a comment noting multi-arg limitation and leave as-is for now since it's a rare pattern.

### 1D. Fix `.sort()` with comparator regex (Issue 10)
`(\w+)\.sort\(([^)]+)\)` stops at first `)` inside `(a, b) => a - b`.

**Fix:** Change regex to use balanced-paren matching: `(\w+)\.sort\((.+)\)` (greedy match to last `)`). This works because sort's callback is always the last arg.

### 1E. Fix nullish coalescing with `std::optional` (Issue 6)
`CUTTLEFISH_UNDEFINED = 0` makes `0` nullish. TypeScript `??` only triggers on `null`/`undefined`.

**Fix:** Use `std::optional<T>` for nullable variables. This requires changes in both packages.

**Strategy (`strategy.ts`):**
- Remove `CUTTLEFISH_UNDEFINED` sentinel
- Add `<optional>` to required includes
- New shimLines using `std::optional`:
  ```cpp
  // Nullish checks: only std::optional and pointers can be nullish
  template<typename T> inline bool cuttlefish_is_nullish(const std::optional<T>& v) { return !v.has_value(); }
  template<typename T> inline bool cuttlefish_is_nullish(T* v) { return v == nullptr; }
  // Plain (non-optional, non-pointer) values are NEVER nullish — fixes 0 ?? 42
  template<typename T, typename = std::enable_if_t<!std::is_pointer_v<T>>>
  inline bool cuttlefish_is_nullish(const T& v) { return false; }
  // Nullish coalescing
  template<typename T, typename U> inline T cuttlefish_nullish(const std::optional<T>& a, const U& b) { return a.value_or(static_cast<T>(b)); }
  template<typename T> inline T cuttlefish_nullish(const T& a, const T& b) { return a; }
  ```
- `nullValue()` returns `std::nullopt` (for `null`/`undefined` literals)

**Transpiler changes:**
- **`expression-to-ir.ts`**: When a variable is initialized with `null`, `undefined`, or has type `T | null | undefined`, mark it in a `nullableVars` set
- **`variables.ts`**: Variables in `nullableVars` get `std::optional<CppType>` type
- **`expression-to-ir.ts`**: `??` operator emits `cuttlefish_nullish(left, right)` which resolves correctly for both optional and non-optional left operands
- **`expression-to-ir.ts`**: `?.` operator wraps the access with `cuttlefish_is_nullish` guard

### 1F. Fix `wrapStringObject` for booleans (Issue 30)
`std::to_string(true)` produces `"1"` instead of `"true"`.

**Fix:** The `wrapStringObject` method can't know the expression type. Instead, handle booleans at the transpiler level — see Part 2E.

### 1G. Fix chained method transforms (Issue 3)
After first transform, e.g. `str.trim()` → `__tc_trim(str)`, subsequent methods like `.toUpperCase()` can't match because `__tc_trim(str)` is not `(\w+)`.

**Fix:** Apply transforms iteratively in a loop until no more matches. After each transform, re-scan for new matches. This handles one level of chaining per iteration.

### 1H. Fix method transforms on non-trivial receivers (Issue 2)
`obj.name.toUpperCase()` — regex `(\w+)\.toUpperCase()` only matches `name.toUpperCase()`.

**Fix:** Change receiver pattern from `(\w+)` to `([A-Za-z_]\w*(?:\.[A-Za-z_]\w*)*)` to match dotted chains. This allows `obj.name`, `this.field`, etc.

### 1I. Add `Math.random()` polyfill (Issue 26, framework side)
`Math.random()` becomes `std::random()` which doesn't exist.

**Fix:** Add a `__tc_random()` polyfill in the native strategy that returns `(double)rand() / RAND_MAX`. Add `<cstdlib>` to required includes.

## Part 2: Transpiler Fixes (`packages/cuttlefish/`)

### 2A. Extend `shouldSkipStringWrap` for method calls (Issue 1)
Method calls that return strings (like `__tc_toUpperCase(str)`) still get wrapped in `std::to_string()`.

**File:** `expression-renderer.ts`

**Fix:** In `shouldSkipStringWrap`, add checks for:
- `method-call` kind where the callee starts with `__tc_` (all `__tc_` string method polyfills return `std::string`)
- `method-call` kind where `knownFunctionReturnTypes` indicates a string return type
- `raw` kind where the value matches `__tc_` prefix or `.c_str()` etc.

### 2B. Fix `resolveLengthProperty` for various cases (Issues 4, 5, 24)
- Call expression receiver returns `strlen(getStr())` — wrong for `std::string` returns
- `this->field.length` always uses `strlen` — wrong for vector fields
- Untracked variables fallback to `.size()` — wrong for `const char*`

**File:** `expression-to-ir.ts`

**Fix:** 
1. For call expressions, check if the function return type is `std::string` → use `.length()` or `.size()` instead of `strlen()`
2. For `this->field`, check the field type from class info before defaulting to `strlen()`
3. For the final fallback, keep `.size()` but add a comment that it may need manual fix for `const char*`

### 2C. Move splice with insertion to IR level (Issue 8)
Splice with insert items can't be reliably handled by regex.

**File:** `expression-to-ir.ts` or `array-methods.ts`

**Fix:** Add splice-with-items handling in `tryLowerArrayAndStringMethods()` to emit proper IR for splice with insertion. This generates a `__tc_splice_insert()` call with proper arg separation.

### 2D. Fix integer division — always promote to double (Issue 11)
`const a = 7 / 2` produces `3` in C++ instead of `3.5`.

**File:** `expression-renderer.ts`

**Fix:** In `renderBinary`, when operator is `/` and the strategy's `defaultNumericType()` is `long long` (or when both operands are integers), emit `(double)(left) / (double)(right)` and cast result to the appropriate type. Add a helper to check if an expression is definitely integer-typed.

**Implementation:**
1. Add `promoteDivisionToDouble(): boolean` to the `PlatformStrategy` interface (returns `true` for native)
2. In `renderBinary`, when operator is `/` and `promoteDivisionToDouble()` is true, emit `static_cast<double>(left) / static_cast<double>(right)`
3. If the result variable is typed as `long long`, the assignment will truncate — matching JavaScript behavior where `let a: number = 7 / 2` gives `3.5` but `let a = 7 / 2` also gives `3.5`. Since JS `/` always returns float, we should always use double division.

### 2E. Fix boolean-to-string in template contexts (Issue 30)
`std::to_string(isValid)` produces `"1"` not `"true"`.

**File:** `expression-renderer.ts`

**Fix:** In `renderStringConcat` and `renderTemplateString`, add a check: if the part/expression has `kind === "boolean"`, render as `(isValid ? "true" : "false")` instead of wrapping with `std::to_string()`.

### 2F. Fix `%lld` format for `long long` (Issue 12)
Identifiers with `long long` type get `%d` format instead of `%lld`.

**File:** `expression-renderer.ts` `inferFormatSpecifier`, `snprintf-helpers.ts` `inferSnprintfArg`

**Fix:** Add a check for `long long` type → use `%lld` format. The native strategy's `defaultNumericType()` returns `"long long"`, so any untyped identifier should default to `%lld`.

### 2G. Fix block-bodied lambdas in expression context (Issue 13)
`renderLambda` emits `{ /* body */ }` for block-bodied lambdas.

**File:** `expression-renderer.ts`

**Fix:** Render the full lambda body in expression context, same as in `renderVarDecl` (statement-renderer.ts). Import the `render` method from statement-renderer or delegate. Since the expression renderer doesn't have a statement renderer, we need to pass one or use a different approach.

**Practical fix:** Have the expression renderer store a reference to the statement renderer and use it for lambda body rendering. Or, more simply, render the lambda body lines inline in the expression renderer.

### 2H. Fix lambda capture to use `[&]` for mutation (Issue 14)
`[=]` copies by value, losing mutations and copying large objects.

**File:** `expression-renderer.ts`, `statement-renderer.ts`

**Fix:** Default to `[&]` (capture by reference) instead of `[=]`. This matches JavaScript closure semantics where the closure captures the variable reference, not the value.

### 2I. Fix `finally` block using RAII guard (Issue 15)
Finally block doesn't run after `return` in try/catch.

**File:** `line-appender.ts`

**Fix:** Generate an RAII guard struct that runs the finally code in its destructor. This guarantees execution regardless of how the try/catch block exits.

**Implementation:**
1. When a `try` statement has a `finallyBlock`, emit a guard struct before the try:
   ```cpp
   struct __finally_guard_0 { 
     ~__finally_guard_0() { /* finally body */ } 
   } __fg0;
   try { ... }
   catch (...) { ... }
   // Guard destructor runs automatically at scope exit
   ```
2. The finally guard struct is emitted as prelude lines before the try block
3. The explicit finally block after catch is removed (or kept as a no-op comment)
4. Use a counter for unique guard names when nested finally blocks exist

### 2J. Fix `do_while` condition rendering (Issue 16)
Condition doesn't apply `fixPointerFieldAccess`.

**File:** `line-appender.ts`

**Fix:** Pass `scopeState.knownVariableTypes` and use the statement renderer (which applies pointer fix) for the condition, or manually apply `fixPointerFieldAccess` to the rendered condition.

### 2K. Fix `typeof` for `long long` (Issue 17)
`typeof` on `long long` variable returns `"object"` instead of `"number"`.

**File:** `expression-to-ir.ts`

**Fix:** Add `"long long"` and `"unsigned long long"` to the numeric type check in the `typeof` handler.

### 2L. Fix binary type inference for `long long` (Issue 18)
Binary expression type inference doesn't handle `long long`.

**File:** `type-resolution.ts`

**Fix:** Add `long long` and `unsigned long long` checks alongside `int`, `float`, `double` in `inferExprCppType` for binary expressions.

### 2M. Fix `console.log()` with no args (Issue 19)
Empty args produces `std::cout <<  << std::endl`.

**File:** `statement-renderer.ts` `transformConsoleCall`

**Fix:** Handle empty args case — emit `std::cout << std::endl` when no args.

### 2N. Fix `new` with object literal args (Issue 21)
Object literal args to `new` are replaced with `0`.

**File:** `expression-to-ir.ts`

**Fix:** Instead of replacing object literal args with `"0"`, render them properly using the object IR rendering.

### 2O. Fix `spread_array` in expression context (Issue 22)
Renders as comment `/* spread_array */`.

**File:** `expression-renderer.ts`

**Fix:** Implement spread array rendering in expression context: construct a temporary vector from the spread source and additional elements.

### 2P. Fix array destructuring rest from non-literal (Issue 23)
Rest element from non-literal array is silently skipped.

**File:** `variables.ts`

**Fix:** When the source is not an array literal, emit a `std::vector` slice: `auto rest = std::vector<T>(arr.begin() + i, arr.end())`.

### 2Q. Fix `instanceof` for non-polymorphic types (Issue 25)
`dynamic_cast` requires polymorphic types.

**File:** `expression-renderer.ts`

**Fix:** Use `static_cast` or typeid-based check instead of `dynamic_cast`. Or add a comment noting the limitation. A pragmatic fix: use `typeid` comparison: `typeid(*obj) == typeid(ClassName)`.

**Better fix:** Emit a helper that uses SFINAE or just use `static_cast` with a null check, since most transpiled classes won't use virtual inheritance.

### 2R. Fix `Math.random()` transpilation (Issue 26)
`Math.random()` becomes `std::random()` which doesn't exist.

**File:** `expression-to-ir.ts`

**Fix:** Add a special case for `Math.random` in the property-access handler (near the `Math` checks). When `expr.name.text === "random"`, emit `{ kind: "raw", value: "__tc_random()" }` instead of `std::random`.

**File:** `expression-to-ir.ts` (formatExpressionText in the inner function)
Also handle `Math.random()` in the call expression path where `receiver.text === "Math"`.

### 2S. Fix snprintf binary/unary/ternary format (Issue 27)
Always uses `%d` even for float results.

**File:** `snprintf-helpers.ts`

**Fix:** For binary/unary/ternary, try to infer the actual type by recursing into sub-expressions. If any sub-expression involves float, use `%g` instead of `%d`.

### 2T. Fix object destructuring pointer access (Issue 28)
Uses `.` instead of `->` for pointer types.

**File:** `variables.ts`

**Fix:** Check if the object variable is a pointer type and use `->` instead of `.` in the property access expression.

### 2U. Fix catch variable binding (Issue 29)
`catch (e)` drops `e`, making it undeclared.

**File:** `line-appender.ts`

**Fix:** Parse the catch clause variable name from the IR (or add it to the IR) and emit `catch (const std::exception& e)` or `catch (const auto& e)`.
