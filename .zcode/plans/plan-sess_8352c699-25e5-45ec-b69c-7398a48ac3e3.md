# Board-package simulator helper + documentation

Add a `createBoardFromDefinition()` helper that derives a fully-configured `SimBoard` from any board package's runtime `BoardDefinition`, so users can simulate a real board (Uno, Nano, ESP32, …) by reusing its pin map, capability flags, ADC resolution/reference, and bus counts — instead of hardcoding them in `createSimBoard()`. No board-package changes required; the data is already runtime-importable.

## The problem this solves

`createSimBoard({ boardType: 'arduino-uno' })` works, but the pin maps are hardcoded in the simulator and only Uno/Nano are recognized (custom boards get no capability pins). Users who already have `@typecad/board-arduino-uno` imported want to reuse *its* authoritative pin map. The blocker (confirmed by investigation): board-package `Pin` objects carry `.number = -1` sentinels at runtime. But the `BoardDefinition` exported by every board package carries the real data — `pins.all[].number` (real Arduino numbers), `pins.all[].capabilities.pwm/.interrupt` (booleans), `peripherals.adc[0].resolution`/`.referenceVoltage`, and bus instance counts — all as plain runtime-importable objects.

## Part 1 — The helper

**New file:** `packages/simulator/src/board/from-definition.ts`

Export `createBoardFromDefinition(def: BoardDefinition): SimBoard`. It derives a `SimBoardConfig` from the definition, calls `createSimBoard()`, then applies ADC resolution/reference to the analog pins.

Key derivation rules (verified against ATmega328P + ESP32 data):
- **digitalPinCount** ← `def.pins.digital.length` (20 for Uno)
- **analogPinCount** ← `def.pins.analog.length` (6 for Uno)
- **pwmPins** ← `pins.all.filter(capabilities.pwm).map(number)` → `[3,5,6,9,10,11]`
- **interruptPins** ← `pins.all.filter(capabilities.interrupt && !unsafe).map(number)`. AVR nuance: `pins.all` marks PD0–PD3 as interrupt-capable, so this yields `[0,1,2,3]` on Uno; document that users can override with the `interruptPins` config option if they want only `[2,3]`. Generic — no AVR special-casing.
- **bus counts** ← `peripherals.{i2c,spi,uart}.length`
- **ADC config**: after construction, iterate `analogPins` and apply `setResolution(adc.resolution)` + `setAnalogReference(adc.referenceVoltage)` when defined (Uno: 10-bit / 5.0V) so `readVoltage()` math is correct out of the box.

**Type dependency:** `@typecad/cuttlefish` added as a devDependency (type-only import of `BoardDefinition` from `@typecad/cuttlefish/api/schema`; erased at runtime). `tsconfig.json` already references `../cuttlefish`.

**Barrel export:** add `createBoardFromDefinition` to `packages/simulator/src/index.ts`.

## Part 2 — Tests

**New file:** `tests/packages/simulator/board-from-definition.test.ts`

Import the real `ArduinoUno` definition from `@typecad/board-arduino-uno` (built dist) and assert:
- `digitalPins.size === 20`, `analogPins.size === 6`
- `pwmPins` keys === `[3,5,6,9,10,11]`
- bus counts: 1 I2C, 1 SPI, 1 UART
- ADC resolution applied: `board.analog(0).getAnalogResolution() === 10`
- ADC reference applied: inject 1023 → `readVoltage()` ≈ 5.0
- Functional: `board.digital(13).high()` → `getBitValue() === 1`
- Generic-shape test: a minimal synthetic `BoardDefinition` (2-bus, 12-bit ADC) proves the helper isn't Uno-specific.
