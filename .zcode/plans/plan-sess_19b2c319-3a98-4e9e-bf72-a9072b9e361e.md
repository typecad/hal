# Relocate runtime-contract interfaces from `@typecad/hal` to `@typecad/simulator`

## Goal & rationale

The exploration overturned my original review's premise. The `types.ts` interfaces (`BasePin`, `II2CBus`, `ISPIBus`, `ISerialPort`, …) are **not** a dead "diverged parallel hierarchy" — they are a live runtime contract: `@typecad/simulator` `implements` 8 of them with real behavioral classes (`SimDigitalPin`, `SimI2CBus`, …), and their *names* are used as string literals by the cuttlefish transpiler to classify compile-time-only types. A literal collapse/merge is impossible (the shim classes are no-op IR emitters; the sim classes are rich stateful objects — structurally incompatible).

The achievable form of "one hierarchy per package" is **relocation**: move the runtime-contract types into `@typecad/simulator` (their sole real consumer), leaving `@typecad/hal` containing only its transpiler-shim surface. After this, each package owns exactly the hierarchy that matches its job.

## What moves vs. stays (final, decisions locked)

**MOVE to `@typecad/simulator/src/contracts.ts`** (new file) — the runtime-contract set consumed by the simulator's `implements` clauses:
- Pin interfaces: `BasePin`, `PWMPin`, `AnalogPin`, `InterruptPin`, `IOutputModePin`, `IInputModePin`
- Bus interfaces: `II2CBus`, `II2CDeviceAccessor`, `ISPIBus`, `ISPIDevice`, `IUARTBus`, `ISerialPort`
- Supporting types: `PinCapabilityFlags`, `IToneAttachment`, `UARTStatusInfo`, `InterruptOptions`, `ErrorPolicy`, `AnalogValue`
- Value enums: `I2CStatus`, `SPIStatus`, `UARTStatus`
- Capability guards (value exports bound to the pin interfaces): `hasPWM`, `hasAnalogInput`, `hasInterrupt`, `assertPWM`, `assertAnalog`, `assertInterrupt`, and the internal `isBasePin` helper

**STAY in `@typecad/hal`** (verified):
- Shim/transpiler types: `PinMode`, `InterruptMode`, `ArchitectureIdentifier`
- Pin-group API: `createPinGroup`, `IPinGroup`, `PinGroupMember`
- Protocol-shape types re-exported by `framework-arduino`: `I2CAddress`, `SPIMode`, `SPIBitOrder`, `SPISettings`
- The two trivial aliases used by hal's own staying code: `InterruptHandler` (used by `interrupts.ts:7,24`) and `DigitalValue` (used by `createPinGroup`). Both stay so no hal→simulator dependency is created.
- The genuinely-dead symbols, dropped entirely: `UARTParity`, `UARTStopBits`, `UARTFlowControl` (zero consumers — confirmed)

## Verification done before planning

- Grepped the whole repo (excluding `node_modules`/`dist`/website build) for every symbol — importer lists are complete.
- Confirmed `interrupts.ts:7,24` is the only internal-hal user of a moving symbol (`InterruptHandler` → stays); `createPinGroup` uses `DigitalValue` (→ stays).
- Confirmed `@typecad/simulator` already depends on `@typecad/hal` (`package.json:18-20`), so the dependency direction (simulator → hal for the staying types) is already established and correct.
- Confirmed the transpiler's string-literal sets (`cuttlefish/src/ir/type-resolution.ts:74-84`, `framework-arduino/src/strategy.ts:748-749`) match **user source-code type names**, not TS import paths — so they need **no changes**. No cuttlefish source file imports any moving symbol as a real TS type.
- `@typecad/simulator/src/types.ts` exists (95 lines, simulator-local types) — but it holds `ISimI2CDevice`/`SimBoardConfig` etc. The relocated interfaces will land in a **separate `contracts.ts`** to keep "HAL-originated contracts" cleanly separable from "simulator-internal types".

## Implementation steps

### Step 1 — Create `packages/simulator/src/contracts.ts`
Cut the moving interfaces/enums/guards verbatim from `packages/hal/src/types.ts` (preserving JSDoc). The file imports the staying aliases it still references from `@typecad/hal`:
```ts
import type { InterruptHandler, DigitalValue } from '@typecad/hal';
import { PinMode } from '@typecad/hal';   // enum value — needed if any contract references PinMode
```
(Check during impl whether any moving interface actually references `PinMode`/`InterruptHandler`/`DigitalValue`; import only what's used. `InterruptOptions` references `InterruptHandler`? `BasePin` methods reference `DigitalValue`/`PinMode`? — wire exactly those.)

### Step 2 — Remove the moved symbols from `packages/hal/src/types.ts`
Delete the moved interfaces/enums/guards. **Keep** `PinMode`, `InterruptMode`, `ArchitectureIdentifier`, `DigitalValue`, `AnalogValue` (only if unused after move — but `AnalogValue` may be referenced by `BasePin.readAnalog?`; if so keep it too and let simulator import it), `InterruptHandler`, `createPinGroup`/`IPinGroup`/`PinGroupMember`, `I2CAddress`/`SPIMode`/`SPIBitOrder`/`SPISettings`. Drop `UARTParity`/`UARTStopBits`/`UARTFlowControl`. Resolve any `PinGroupMember`/`createPinGroup` reference to `DigitalValue` against the staying alias.

### Step 3 — Update `packages/hal/src/index.ts` re-exports
Remove re-exports of every moved/deleted symbol (the `export type { BasePin, … }`, `export { I2CStatus, … }`, `export { UARTParity, … }` lines). Keep re-exports of staying symbols. **Add nothing new.**

### Step 4 — Update `packages/simulator/src/index.ts`
Re-export the relocated contracts so simulator consumers and external users can import them from `@typecad/simulator`:
```ts
export type { BasePin, PWMPin, AnalogPin, InterruptPin, IOutputModePin, IInputModePin,
  II2CBus, II2CDeviceAccessor, ISPIBus, ISPIDevice, IUARTBus, ISerialPort,
  PinCapabilityFlags, IToneAttachment, UARTStatusInfo, InterruptOptions, ErrorPolicy } from './contracts.js';
export { I2CStatus, SPIStatus, UARTStatus } from './contracts.js';
export { hasPWM, hasAnalogInput, hasInterrupt, assertPWM, assertAnalog, assertInterrupt } from './contracts.js';
```

### Step 5 — Repoint simulator source imports
In each of these files, change the `from '@typecad/hal'` import for **moved** symbols to `from '../contracts.js'` (or `'./contracts.js'`), while **leaving** imports of staying symbols (`PinMode`, `InterruptHandler`, `DigitalValue`, `AnalogValue`) on `@typecad/hal`:
- `packages/simulator/src/gpio/digital-pin-sim.ts` — split: `BasePin, IToneAttachment, PinCapabilityFlags` → contracts; `PinMode`, `DigitalValue` stay on hal
- `packages/simulator/src/gpio/pwm-pin-sim.ts` — `PWMPin, IToneAttachment, AnalogValue` → PWMPin/IToneAttachment to contracts, AnalogValue stays hal (drop dead `PinMode`/`IToneAttachment` imports noted in review)
- `packages/simulator/src/gpio/analog-pin-sim.ts` — `AnalogPin` → contracts; `AnalogValue` stays hal
- `packages/simulator/src/gpio/interrupt-sim.ts` — `InterruptPin, InterruptOptions` → contracts; `InterruptHandler` stays hal
- `packages/simulator/src/bus/i2c-sim.ts` — `I2CStatus`(value)→contracts; `II2CBus, II2CDeviceAccessor, ErrorPolicy`(types)→contracts; `I2CAddress`(type) stays hal
- `packages/simulator/src/bus/spi-sim.ts` — `SPIStatus`(value)→contracts; `ISPIBus, ISPIDevice, BasePin, ErrorPolicy`(types)→contracts; `SPIMode, SPIBitOrder, SPISettings`(types) stay hal
- `packages/simulator/src/bus/serial-sim.ts` — `UARTStatus`(value)→contracts; `ISerialPort, UARTStatusInfo, ErrorPolicy`(types)→contracts
- `packages/simulator/src/board/board-sim.ts` — the dead `BasePin, AnalogPin, PWMPin, InterruptPin` type-only import (line 5, unused in body per exploration) → remove entirely

### Step 6 — Repoint example imports
- `examples/17-pin-validation.ts:13-14` — `hasPWM, hasAnalogInput, hasInterrupt, assertPWM` + `PWMPin` → `from '@typecad/simulator'`
- `examples/25-debounce-button.ts:15` — `IInputModePin` → `from '@typecad/simulator'`; `InterruptHandler` stays `from '@typecad/hal'` (split into two import lines)

### Step 7 — `framework-arduino` needs NO changes
`I2CAddress`/`SPIMode`/`SPIBitOrder`/`SPISettings` stay in hal, so `framework-arduino/src/arduino/{index,i2c-arduino,spi-arduino,stubs-uno}.ts` re-exports and imports are unaffected.

### Step 8 — Transpiler string sets need NO changes
`cuttlefish/src/ir/type-resolution.ts` and `framework-arduino/src/strategy.ts` string literals match user source-code type names, not TS import paths.

## Risk & reversibility
- All changes are import-path rewiring + cut/paste of type declarations — no behavioral logic changes. Easily reversible via git.
- If a moved interface is discovered to have an additional hidden importer (the exploration was exhaustive, but), the symptom is a `tsc` "cannot find name" error pointing exactly at the fix.
- No runtime/bundling impact for type-only moves; the three moving enums (`I2CStatus`/`SPIStatus`/`UARTStatus`) are value exports but only consumed by the simulator, which will now own them.
