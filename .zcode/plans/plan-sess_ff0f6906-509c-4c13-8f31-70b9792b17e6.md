## AVR Static-Array Async Runtime — Implementation Plan

### Goal
Give the HAL `Async` singleton (`Async.sleep`/`yield`/`sleepUntil`/`currentTask`) a heap-free runtime on AVR (ATmega328P, 2 KB SRAM) so it compiles and runs. The existing heap-based `Promise<T>` runtime (which needs `<vector>`/`<string>`) stays for ESP32/ESP8266/etc. The HAL async test (`15-async.test.ts`) then runs on the Uno instead of being skipped.

### Root cause recap
- HAL `Async.*` methods lower to 4 symbols: `__cuttlefish_async_sleep`, `__cuttlefish_async_yield`, `__cuttlefish_async_sleep_until`, `__cuttlefish_async_current_task`, plus `cuttlefish_pump_microtasks()` (called from `loop()`).
- These are defined inside the heap-based promise runtime (`packages/cuttlefish/src/api/shared/promise-runtime.ts`).
- The Arduino strategy only emits that runtime when `stdlib.hasVector && stdlib.hasString` (`strategy.ts:622`). AVR has both `false`, so the symbols are undefined → link failure.
- Separately, `async function`+`await delay()` already works heap-free on AVR via `async-state-machine.ts` (a separate path — not touched).

### New file: `packages/cuttlefish/src/api/shared/async-runtime-static.ts`
A new generator `generateStaticAsyncRuntime(queueCapacity: number): string` returning a C++ string that defines the same 4 global symbols + `cuttlefish_pump_microtasks()`, with **zero heap allocation**:

```cpp
namespace typehal_async_static {
  struct Task { bool active; bool (*fn)(void*); void* ctx; };   // function ptr + raw ctx, no std::function
  class StaticTaskQueue {
    static const int CAP = <queueCapacity>;   // 8 on AVR
    Task _tasks[CAP];
    int _count;
  public:
    StaticTaskQueue() : _count(0) {}
    bool enqueue(bool (*fn)(void*), void* ctx);
    void pump();   // runs each ready task once, removes completed (fn returns false)
  };
  // Timed slots for Async.sleep / sleepUntil: { active, deadline, periodMs, repeat }
  struct Timer { bool active; bool repeat; unsigned long deadline; unsigned long periodMs; };
  class StaticTimerWheel { Timer _timers[CAP]; ... arm(ms), armRepeat(ms), tick(now) ... };
}
```

- `__cuttlefish_async_sleep(ms)` → arms a one-shot timer; no return value (void). On AVR the HAL methods' dummy `Promise<void>` JS return is already discarded by the transpiler (they're statement-context rawCpp).
- `__cuttlefish_async_yield()` → enqueues a trivial one-shot task that completes next pump.
- `__cuttlefish_async_sleep_until(pollMs)` → arms a periodic timer at `pollMs` (the condition re-check is caller-side, matching the existing comment in promise-runtime.ts:200).
- `__cuttlefish_async_current_task()` → returns `"main"` (identical to existing).
- `cuttlefish_pump_microtasks()` → calls both `StaticTimerWheel::tick(millis())` and `StaticTaskQueue::pump()`.

No `std::function`, `std::vector`, or `std::string`. Function-pointer + `void*` ctx only; fixed arrays. `CAP` small (8) for AVR SRAM budget.

**Why not full `Promise<T>`/`.then` chaining on AVR?** AVR can't host a generic promise chain without heap/type-erasure. The HAL `Async` API is fire-and-forget scheduling (sleep/yield/sleepUntil/currentTask) — it doesn't expose `.then`/`.catch`. So a timer-wheel + trivial task-queue covers the actual HAL contract without needing the full promise machinery. The `async function`+`await` path already has its own heap-free state machine, untouched.

### Wire it in: `packages/framework-arduino/src/strategy.ts` (`generateNativePolyfills`, ~line 618-636)
Change the async branch from a single gated path to a target-branched one:

```ts
const hasAsync = program.functions.some(fn => fn.isAsync) || programUsesAsyncRuntime(program);
if (hasAsync) {
  const architecture = ctx?.architecture ?? arduinoCtx(ctx)?.buildTarget?.split(":")?.[1]?.toLowerCase();
  const stdlib = this.getStdLibSupport(architecture);
  if (stdlib.hasVector && stdlib.hasString) {
    // existing heap-based promise runtime (ESP32/ESP8266/rp2040/samd) — unchanged
    helpers.push({ ..., helperStructs: [generatePromiseRuntime(...)], hasPromiseRuntime: true });
  } else {
    // AVR / megaavr: heap-free static runtime
    helpers.push({
      kind: "polyfill", id: "async_runtime", domain: "arduino",
      requiredIncludes: [],                 // no <vector>/<functional>/<string>
      forwardDeclarations: [], helperStructs: [generateStaticAsyncRuntime(8)],
      helperFunctions: [], shimMacros: [], dependencies: [],
      hasPromiseRuntime: true,             // so cuttlefish_pump_microtasks() is injected into loop()
    });
  }
}
```

`hasPromiseRuntime: true` on the AVR polyfill ensures the existing `cuttlefish_pump_microtasks()` injection in `loop()` (function-emitter-impl.ts:290, 341-350) activates unchanged — the static runtime defines that symbol.

### Also fix the latent queue-capacity bug
`strategy.ts:629` splits `buildTarget` on `:` and checks `[0] === "arduino"` (always true for any `arduino:*` FQBN), so the `256` branch is dead. Replace with an architecture-based capacity: derive from the `architecture` variable already computed on the line above (esp32 → 256, avr → 8). Keeps ESP32 behavior correct.

### Un-skip the HAL async test
`packages/hal/tests/15-async.test.ts` currently has `// @typecad-skip-target avr:`. Remove that directive (keep the file). The test exercises `Async.sleep/yield/sleepUntil/currentTask` — all now link on AVR.

### Non-goals
- Not touching `async-state-machine.ts` (the `async function`+`await` path already works on AVR)
- Not removing or altering the existing `Promise<T>` runtime (ESP32 and others keep it)
- Not implementing `.then`/`.catch`/promise chaining on AVR (the HAL API doesn't need it)
- Not addressing the UART skip (separate single-UART hardware constraint)
