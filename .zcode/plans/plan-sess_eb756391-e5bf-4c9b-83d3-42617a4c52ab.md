# Plan: Fix 5 HAL codegen bugs

## Root-cause summary (verified against transpiler source)

| Bug | Root cause |
|-----|-----------|
| BUG-1 | HAL rawCpp templates unconditionally append `.c_str()` to every string param. When the param is a string *literal* it renders as `"label".c_str()` → invalid C++. Fix is **transpiler-side**: append `.c_str()` at substitution time only when the arg is NOT a string literal. |
| BUG-2/3 | `power.ts` uses `const arch = board(...)` then `if (arch === ...)`. The HAL method-body loop has no `VariableStatement` handler, so `arch` never binds → `if` mis-folds to false on every board. ESP32 sleep is dead code. |
| BUG-4 | `timing.ts` hardcodes `rawCpp("return ESP.getFreeHeap();")`, breaking AVR. The `timing.free_heap` semantic op + IR type + peripheral tracking + strategy case all already exist end-to-end — but the HAL never produces the op (no `getFreeHeap()` in emit.ts), and the strategy case returns a stub `0`. |
| BUG-5 | `uart.ts` printf uses rawCpp with BUG-1 `.c_str()`. The `uart.printf` op + IR type + strategy case all exist — but emit.ts has no `uartPrintf` producer, so the op is never produced and the strategy case is dead. |

## Approach per bug

### BUG-1 — transpiler-side `.c_str()` handling
**Files:** `packages/cuttlefish/src/ir/hal/hal-emitter.ts`

- In `resolveExpressionText`'s template-literal interpolation path (the `isTemplateExpression` branch ~line 242-250), the substituted text for a `${param}` slot is either a quoted literal (`"label"`, from `renderExprAsText` case `"string"`) or a bare identifier (`myVar`, case `"identifier"`).
- Add a helper `applyCStrConversion(templateHead, resolvedArgText)`: when interpolating, if the literal text immediately following the `${...}` slot is `.c_str()` AND the resolved arg text starts with `"`, strip the `.c_str()` from the following text (so `"label".c_str()` → `"label"`, while `myVar.c_str()` is unchanged).
- This keeps the HAL source idiomatic (`${key}.c_str()`) and makes the transpiler literal-aware — consistent with the existing `maybeEscapeResolvedText` helper that already detects string-literal-vs-identifier in this same module.
- **No HAL source changes for BUG-1** — the templates stay as written.
- **Update the test** at `tests/packages/cuttlefish/hal-lowering-coverage.test.ts:638-653, 774-812` that currently asserts the *broken* `"label".c_str()` output. Correct expected output to `"label"` for literals (and keep `myVar.c_str()` for the variable case at line 675-684).

### BUG-2/3 — Power deepSleep/lightSleep (HAL-source fix)
**File:** `packages/hal/src/power.ts`

- Inline the board lookup so the existing `if`-folder resolves it: replace `const arch = board(...); if (arch === "esp32")` with `if (board("architecture") === "esp32")` for both `deepSleep` and `lightSleep`.
- Widen the ESP32 family check: since the transpiler's `===` folding handles only a single string comparison, emit a disjunction that the folder can't collapse — instead, restructure to check AVR first (the negated case): `if (board("architecture") === "avr") { /* not supported */ } else { /* esp32-family sleep */ }`. This makes ESP32/C3/C6/S3 all hit the sleep branch (correct, since they all support `esp_deep_sleep_start`), and keeps the fold working.
- **Add ESP32 regression test** in `tests/packages/cuttlefish/hal-lowering-coverage.test.ts`: use `transpileESP32(...)` (already exists in `tests/setup.ts:112`) to assert `esp_sleep_enable_timer_wakeup` and `esp_deep_sleep_start` ARE emitted for ESP32. Keep the existing AVR test (now asserting the corrected AVR branch).

### BUG-4 — freeHeap (route through existing semantic op)
**Files:** `packages/hal/src/emit.ts`, `packages/hal/src/timing.ts`, `packages/framework-arduino/src/strategy.ts`

- Add `export function getFreeHeap(): number { return 0; }` to `emit.ts` (alongside `getMillis`/`getMicros`).
- Add `case "getFreeHeap": return { operation: "timing.free_heap" };` to `hal-plugins.ts` (alongside the `getMillis`/`getMicros` cases).
- In `timing.ts`, replace `rawCpp("return ESP.getFreeHeap();")` with `return getFreeHeap();` (both the `TimingClass.freeHeap()` method and the standalone — the standalone already delegates to `Timing.freeHeap()`).
- Upgrade the Arduino strategy case at `strategy.ts:1362` from `return { expression: "0" };` to `return { expression: "Timing.freeHeap()" };` so it calls the arch-aware polyfill that `shimLines()` already emits (ESP32→`ESP.getFreeHeap()`, AVR→`__heap_start` trick, other→0).
- **Unskip** the test at `tests/semantic-cpp.test.ts:108` (`it.skip("emits heap monitoring routine")`) and update its expectation from `const auto free_ = 0;` to the real `Timing.freeHeap()` expression. Add an ESP32 variant asserting `ESP.getFreeHeap()`.

### BUG-5 — Serial.printf (route through existing semantic op)
**Files:** `packages/hal/src/emit.ts`, `packages/hal/src/uart.ts`, `packages/cuttlefish/src/ir/hal/hal-plugins.ts`

- Add `export function uartPrintf(port: string, format: any, args: any[]): void {}` to `emit.ts` (alongside `uartPrintln`).
- Add `case "uartPrintf":` to `hal-plugins.ts` producing `{ operation: "uart.printf", port, format, args }` (the op interface `UartPrintfOp` already exists at `hal-op-ir.ts:398`).
- In `uart.ts`, replace the `rawCpp(...)` body of `printf` with `uartPrintf(this._port, format, args)`.
- The strategy case at `strategy.ts:1434` already renders `${op.port}.printf(${op.format}, ${op.args.join(", ")})` correctly — no strategy change. The `format` arg will render as a quoted literal `"fmt"` (BUG-1 fix applies) for literal calls and as a bare identifier for variables, both valid for `printf`.
- **Add test** in `tests/packages/cuttlefish/hal-lowering-coverage.test.ts` asserting `Serial.printf("count=%d", 5)` emits `Serial.printf("count=%d", 5)` (no `.c_str()`), and a variable-format variant.
