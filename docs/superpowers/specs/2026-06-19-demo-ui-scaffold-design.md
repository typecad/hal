# Design: `demo-ui` project scaffold

**Date:** 2026-06-19
**Branch:** `feat/ui-graphics-library`
**Status:** Approved

## Goal

Create a new demo project at `./demo-ui` (a sibling of the existing `./demo`)
that targets the ESP32 DevKit using the Arduino framework. It is a **bare
scaffold** — a minimal, transpile/compile-ready project with no UI content yet.
It exists to host future UI-graphics work on this branch.

## Context

- The existing `./demo` targets AVR / Arduino Uno (ATmega328P).
- This branch (`feat/ui-graphics-library`) is building a UI graphics library.
  `demo-ui` is the eventual home for UI demos, but per the user's decision this
  scaffold carries **no `@typehal/ui` usage yet** — just a runnable ESP32
  skeleton that future work builds on.
- The repo is an npm workspaces monorepo; `demo` is a workspace member.

## Layout

A new sibling directory at the repo root, mirroring `./demo`:

```
demo-ui/
├── cuttlefish.config.ts   # ESP32 + framework-arduino + arduino-cli
├── cuttlefish-env.d.ts    # hand-seeded copy of demo/'s; regenerated by transpiler
├── eslint.config.mjs      # copied verbatim from demo/
├── package.json           # workspace "*" deps
├── tsconfig.json          # copied verbatim from demo/
└── src/
    └── main.ts            # minimal ESP32 blinky scaffold
```

## Component details

### `cuttlefish.config.ts`

Based on `demo/cuttlefish.config.ts` with ESP32 substitutions:

| Field | Value | Rationale |
|---|---|---|
| `entry` | `'./src/main.ts'` | matches demo/ |
| `target` | `'esp32'` | valid `ArchitectureIdentifier`; profile.ts has an `esp32` variant |
| `mcu` | `'@typecad/mcu-esp32'` | **required** field per `CuttlefishConfig` schema (not optional) |
| `board` | `'@typecad/board-esp32-devkit'` | user-specified |
| `framework` | `'@typecad/framework-arduino'` | user-specified |
| `frameworkData.buildTarget` | `'esp32:esp32:esp32'` | FQBN advertised by the board package (`build.frameworks.arduino`); matches the profile's `esp32:esp32:` A0 override |
| `output.framework` | `'arduino'` | |
| `output.optimize` | `'size'` | matches demo/ |
| `output.outDir` | `'./out'` | matches demo/ |
| `toolchain.type` | `'arduino-cli'` | user chose arduino-cli toolchain |
| `console.baudRate` | `115200` | ESP32 default; confirmed by user |

The header comment will be rewritten to describe the ESP32 target rather than
the AVR demo's "first AVR demo" narrative.

### `cuttlefish-env.d.ts`

Copied verbatim from `demo/cuttlefish-env.d.ts`. This file is auto-generated by
the transpiler on first run; the seeded copy just gives TypeScript something to
type-check against before the first transpile. The module-re-export block at the
bottom will point at the ESP32 board package (`@typecad/board-esp32-devkit`)
instead of `@typecad/board-arduino-uno`, and the header comment will reflect
the new board. (Anything board-pin-specific is regenerated by the transpiler,
so only the package name in the `declare module '@typecad'` block is changed.)

### `package.json`

- `name`: `demo-ui`
- `description`: ESP32 DevKit demo using the TypeCAD transpiler
- `type`: `module`
- `scripts`: copied from `demo/package.json` (`build`, `compile`, `upload`,
  `transpile`, `lint`)
- `dependencies` (workspace `"*"`):
  - `@typecad/framework-arduino`
  - `@typecad/board-esp32-devkit`
  - `@typecad/mcu-esp32`
- `devDependencies`: `eslint`, `@typescript-eslint/parser`,
  `@typescript-eslint/eslint-plugin` (matches demo/)

### `tsconfig.json`

Copied verbatim from `demo/tsconfig.json`.

### `eslint.config.mjs`

Copied verbatim from `demo/eslint.config.mjs`. It imports
`../eslint-transpiler-rules.mjs`; since `demo-ui` is a sibling of `demo` at the
repo root, that relative path resolves identically.

### `src/main.ts`

A minimal, transpile-clean ESP32 blinky:

- Import the on-board LED from `@typecad/board-esp32-devkit` (`LED` → GPIO2).
- Configure it as an output.
- Top-level call toggles the LED once and logs a startup banner. (The framework
  synthesizes `setup()` from top-level statements and an empty `loop()`; this
  matches how `demo/src/main.ts` is structured.)

The point is a transpile-clean, dependency-correct skeleton — not a meaningful
program. No `loop()` busy-wait blink; keep it one-shot like the AVR demo.

## Workspace wiring

Add `"demo-ui"` to the `workspaces` array in the **root** `package.json`, so
the `"*"` workspace dependencies resolve and `npm install` links the local
packages. Insert it next to the existing `"demo"` entry.

## Out of scope (YAGNI)

- No `@typehal/ui` usage — bare scaffold only.
- No ILI9341 / graphics driver wiring.
- No `upload` port hardcoding (the `upload` script keeps the demo's `COM7`
  placeholder; it's a script string, not exercised by transpile/compile).
- No README (demo/ has a large one; a scaffold doesn't need it — can be added
  when the project gains UI content).

## Testing / verification

After scaffolding:

1. `npm install` (from repo root) to link the new workspace.
2. `cd demo-ui && npm run build` — should transpile `src/main.ts` to
   `./out` without errors.
3. `npm run lint` — should pass (eslint config + parser resolve).
4. (Optional, only if esp32 Arduino core is installed) `npm run compile` —
   should invoke `arduino-cli compile --fqbn esp32:esp32:esp32`.

Step 4 is hardware-environment-dependent; a clean transpile (step 2) and lint
(step 3) are the success bar for this scaffold.
