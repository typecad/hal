# demo-ui Capability Showcase Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recreate `demo-ui` from scratch as a 10-screen capability showcase that exercises every supported HTML element and CSS property of the cuttlefish UI transpiler, themed via the neobrutalism token system.

**Architecture:** Pure demo authoring — no transpiler/UI-package source changes. Three new/rewritten files under `demo-ui/src/` (`showcase.ui.html`, `showcase.neobrutalism.css`, `main.ts`) plus one config edit. Old `hello.*` files stay on disk unreferenced. Because `display.themeCss` replaces the sibling `.ui.css` entirely (`packages/cuttlefish/src/ui/ui-registry.ts:83-88`), the new `.neobrutalism.css` holds `@font-face` + tokens + `@keyframes` + all element rules in one file. "Tests" are the transpile + compile cycle, run after each task.

**Tech Stack:** cuttlefish UI (HTML/CSS → C++), TypeScript (`main.ts`), Arduino ESP32 core, ILI9341.

**Spec:** `docs/superpowers/specs/2026-06-29-demo-ui-capability-showcase-design.md`

**Build/test loop (run from `demo-ui/`):**
- Transpile + render check: `npx cuttlefish build` (exit 0 = success; read warnings).
- Full compile to `esp32:esp32:esp32`: `npx cuttlefish build --compile` (exit 0 = success).
- Preview server: `npx cuttlefish preview --config ./cuttlefish.config.ts` (opens `http://127.0.0.1:5xxx/`).

**Verified facts used by this plan:**
- Display: 320×240 landscape ILI9341.
- Supported tags (html-parser.ts): `screen body div header footer nav main section article aside span p h1 h2 h3 h4 h5 h6 text button view check select option label radio progress range input keyboard row key style a img list canvas br`.
- `screen.<id>` is auto-typed in the generated `*.ui.d.html.ts` for **every** id'd node (container or leaf); the type is derived from the tag (e.g. `view`/`body` → `ViewElement`, `text`/`h2`/`p` → `TextElement`).
- Build-time warning is **expected** for `border-bottom` etc. ("runtime draws uniform borders only"); use shorthand `border` for real borders, and demonstrate per-side borders explicitly on the `box` screen as a documented best-effort.
- Per-side `padding`/`margin` (e.g. `padding: 2px 4px`) are supported; longhand `padding-bottom` warns.
