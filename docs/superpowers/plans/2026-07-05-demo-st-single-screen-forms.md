# demo-st single-screen forms demo — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rewrite `demo-st/src/showcase.ui` into a single non-scrolling 320×480 screen that demos every cuttlefish form control in a two-column grid, and delete the dead files (`main.ts`, `showcase.ui.html`, `showcase.neobrutalism.css`) the single-file entry orphaned.

**Architecture:** One single-file `.ui` component carries its own `<script>` (reactive wiring), `<style>` (theme + layout), and template (form elements in flex rows). No scroll containers, no master-detail, no nav. The existing `<keyboard>` template stays so text/number inputs work on hardware. Dead files are deleted because the transpiler ignores them for a `.ui` entry.

**Tech Stack:** cuttlefish transpiler (`@typecad/cuttlefish`), `@typecad/ui` (`ui.signal` / `ui.bind` / `onChange`), Arduino ESP32 target, ST7796S 320×480 SPI TFT + FT6336U capacitive touch.

**Spec:** `docs/superpowers/specs/2026-07-05-demo-st-single-screen-forms-design.md`

**Repository conventions (from `AGENTS.md`):**
- Generated `src/out/*/main.ino` / `*.ino` is **not** the source of truth — change the runtime/header/emitter code or the `.ui` source, then regenerate. Never hand-edit generated `.ino`.
- Build `@typecad/cuttlefish` before running anything that imports package exports, so tests/compile don't exercise stale `dist`.

```html
<script>
  // showcase.ui — single-screen forms demo.
  // Reactive state + bindings for the form controls. The template owns the
  // event attributes and {interpolation} sites; this script owns the signals
  // and the ui.bind() effects that drive live text, color, and meter state.

  import { ui } from '@typecad/ui';

  ui.mount(screen);

  // ── Button: tap counter ───────────────────────────────────────────────────
  export const count = ui.signal(0);

  export function incrementTaps() {
    count.set(count() + 1);
  }

  // ── Text + number inputs: commit counters ─────────────────────────────────
  export const nameCommits = ui.signal(0);
  export const ageCommits = ui.signal(0);

  export function captureName() {
    nameCommits.set(nameCommits() + 1);
    console.log('name:', screen.formName.text);
  }

  export function captureAge() {
    ageCommits.set(ageCommits() + 1);
    console.log('age:', screen.formAge.text);
  }

  // ── Reactive bindings: each control drives a visible effect ───────────────
  ui.bind(screen.featureStatus, 'text', () => screen.formCheck1.value ? 'feature: enabled' : 'feature: disabled');
  ui.bind(screen.featureLamp, 'background', () => screen.formCheck1.value ? '#29d391' : '#4b5563');
  ui.bind(screen.modeStatus, 'text', () => screen.formSelect1.value == 0 ? 'mode: alpha' : screen.formSelect1.value == 1 ? 'mode: beta' : 'mode: gamma');
  ui.bind(screen.modeAccent, 'background', () => screen.formSelect1.value == 0 ? '#38bdf8' : screen.formSelect1.value == 1 ? '#f6c84c' : '#b985ff');
  ui.bind(screen.radioStatus, 'text', () => screen.formRadio2.value ? 'speed: fast' : 'speed: calm');
  ui.bind(screen.volumeStatus, 'text', () => `volume: ${screen.formRange1.value}`);
  ui.bind(screen.formProg, 'value', () => screen.formRange1.value * 10);
  ui.bind(screen.formProgressCaption, 'text', () => `meter: ${screen.formRange1.value * 10}%`);
</script>
```

- Kept verbatim: `count`/`nameCommits`/`ageCommits` signals, `incrementTaps`/`captureName`/`captureAge`, and all 8 form `ui.bind(...)` lines.
