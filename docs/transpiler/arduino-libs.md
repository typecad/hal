# Arduino Library Integration

TypeCode automatically discovers Arduino libraries installed via `arduino-cli` and generates TypeScript type definitions for them. This allows you to use existing Arduino C++ libraries with full TypeScript type safety.

## Overview

When you import an Arduino library in your TypeScript code:

```typescript
import { BH1750 } from 'BH1750';
import { SHT3x } from 'Microfire_SHT3x';
```

TypeCode will:

1. **Discover** the library from your Arduino installation
2. **Parse** the C++ headers to extract class definitions
3. **Generate** TypeScript type definitions (`.d.ts`)
4. **Create** usage documentation (`USAGE.md`)
5. **Transpile** the imports to proper Arduino `#include` directives

## Installation

Ensure your Arduino libraries are installed via `arduino-cli`:

```bash
# Install a library
arduino-cli lib install BH1750

# List installed libraries
arduino-cli lib list
```

## Generated Files

When TypeCode encounters an unrecognized import that matches an Arduino library name, it generates:

```
node_modules/@types/{LibraryName}/
├── index.d.ts      # TypeScript type definitions
├── package.json    # Package metadata for module resolution
└── USAGE.md        # Usage guide with examples
```

### Example: BH1750 Light Sensor

**Generated `index.d.ts`:**

```typescript
/**
 * Arduino library: BH1750
 * 
 * Auto-generated by TypeCode from Arduino library C++ headers.
 * Arduino peripheral types (TwoWire, HardwareSerial, etc.) are mapped to TypeCode equivalents.
 * 
 * You can manually edit this file to:
 *   - Add missing methods or properties
 *   - Fix incorrect type mappings
 *   - Add JSDoc documentation
 * 
 * To regenerate: delete this file and re-run typecode transpile.
 */

export declare class BH1750 {
  constructor(addr?: number);
  begin(mode?: number, addr?: number, i2c?: I2C0): boolean;
  configure(mode: number): boolean;
  readLightLevel(): number;
}
```

**Generated `USAGE.md`:**

```markdown
# BH1750 - TypeCode Usage Guide

## Classes

### BH1750

#### Constructor
```typescript
import { BH1750 } from 'BH1750';

const sensor = new BH1750(0x23);
```

#### Methods

| Method | Parameters | Returns |
|--------|------------|---------|
| `begin()` | mode?: number, addr?: number, i2c?: I2C0 | boolean |
| `readLightLevel()` | none | number |

#### Example Usage
```typescript
import { BH1750 } from 'BH1750';

const device = new BH1750(0x23);
device.begin();

const lux = device.readLightLevel();
```
```

## Type Mappings

TypeCode automatically maps Arduino C++ types to TypeScript equivalents:

| Arduino C++ | TypeCode TypeScript | Notes |
|-------------|---------------------|-------|
| `TwoWire`, `TwoWire*`, `TwoWire&` | `I2C0` | I2C peripheral instance |
| `SPIClass`, `SPIClass*`, `SPIClass&` | `SPI0` | SPI peripheral instance |
| `HardwareSerial`, `HardwareSerial*` | `UART0` | Serial port instance |
| `int`, `uint8_t`, `uint16_t`, `int32_t` | `number` | Integer types |
| `float`, `double` | `number` | Floating point |
| `bool` | `boolean` | Boolean |
| `String`, `const char*` | `string` | String types |

### Peripheral Mapping

When passing peripherals to Arduino libraries:

```typescript
import { SHT3x } from 'Microfire_SHT3x';
import { I2C0 } from '@typecode';

const sensor = new SHT3x();
sensor.begin(I2C0, 0x44);  // I2C0 maps to Arduino's Wire
```

The transpiler converts:
- `I2C0` → `Wire`
- `I2C1` → `Wire1`
- `SPI0` → `SPI`
- `UART0` → `Serial`

## C++ Namespace Handling

Some Arduino libraries use C++ namespaces. TypeCode handles these automatically:

### Example: Microfire SHT3x

The library defines a class inside a namespace:

```cpp
namespace Microfire {
  class SHT3x {
    // ...
  };
}
```

TypeScript code uses the simple name:

```typescript
import { SHT3x } from 'Microfire_SHT3x';

const sensor = new SHT3x();
```

Generated C++ code uses the fully qualified name:

```cpp
Microfire::SHT3x* sensor = new Microfire::SHT3x();
```

## Native C++ Modules

For libraries that require custom C++ implementation (not just headers), you can create native modules:

### Structure

```
src/lib/
├── MySensor.h      # C++ header
├── MySensor.cpp    # C++ implementation
└── MySensor.d.ts   # TypeScript declarations
```

### TypeScript Declarations

Create a `.d.ts` file with a special header comment:

```typescript
// @native-include "MySensor.h"

export declare class MySensor {
  constructor();
  begin(): boolean;
  read(): number;
}
```

The `@native-include` directive tells TypeCode to:
1. Include the header file in the generated Arduino sketch
2. Copy the `.cpp` file to the output directory

### Importing Native Modules

```typescript
import { MySensor } from './lib/MySensor';

const sensor = new MySensor();
sensor.begin();
```

## Manual Editing

Generated type definitions are best-effort. You can manually edit them to:

- Add missing methods or properties
- Fix incorrect type mappings
- Add JSDoc documentation for better IDE support

### Editing Workflow

1. Navigate to `node_modules/@types/{LibraryName}/index.d.ts`
2. Make your changes
3. TypeScript will pick up the changes immediately

To regenerate (overwriting manual changes):
1. Delete the `node_modules/@types/{LibraryName}` directory
2. Re-run `npx typecode sketch.ts`

## Limitations

### Template Classes

C++ template classes are not automatically parsed. You'll need to manually create type definitions for these.

### Macros and Preprocessor

C++ macros cannot be represented in TypeScript. Constants defined via `#define` need manual type definitions.

### Overloaded Methods

Method overloading is supported, but complex overload patterns may require manual adjustment.

### Inheritance

Class inheritance from Arduino base classes (like `Print`) is flattened. Methods from base classes should be manually added if needed.

## Troubleshooting

### Library Not Found

If TypeCode doesn't find your library:

1. Verify it's installed: `arduino-cli lib list`
2. Check the library name matches the import exactly (case-sensitive)
3. Ensure the library has a `.h` header file matching the library name

### Wrong Method Signatures

If generated method signatures don't match the actual library:

1. Edit `node_modules/@types/{LibraryName}/index.d.ts` manually
2. Check the library's `.h` file for the correct signatures
3. Consider contributing improvements to the TypeCode parser

### Missing Methods

Some methods may not be detected if they:
- Use complex C++ syntax (templates, macros)
- Are defined in separate header files
- Use non-standard declaration patterns

Manually add these to the `.d.ts` file.
